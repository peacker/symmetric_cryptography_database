Full website-vs-source verification pass (2026-07-16)
======================================================

Read essentially every locally-available reference PDF against its family's
stored notes/influences/construction tags (~330 of 410 families; the other
~79 have no local reference at all, see item 6 above, and were sanity-checked
against general crypto literature instead). Fixed two systematic issues along
the way (see git log: "Full source audit: fix RC5..." and "...classify 18
unclassified 2019 NIST-LWC AEAD modes"). One new gap surfaced that needs a
manual decision or a fetched paper, plus everything already listed above in
items 1-6 is still open and unchanged:

8. LOKI89/91's REAL PAPER IS MISSING, AND THE AUDIT TOOLING HIDES IT
   -------------------------------------------------------------------
   The `loki` family (data/primitive_families.yaml) cites `loki_ref` (Brown,
   Pieprzyk, Seberry, "LOKI — A Cryptographic Primitive for Authentication
   and Secrecy Applications," AUSCRYPT 1990) with no local copy — there
   never was one fetched for this specific paper.

   This wouldn't normally be a problem (it would just show up as
   KNOWN_MISSING like the other ~79 stubs), except scripts/reference_pdfs.py's
   fuzzy filename-matcher currently mis-resolves `loki` to
   references/1998-loki97.pdf — the LOKI97 AES-candidate paper, a much later
   and structurally unrelated design by the same research lineage. Because of
   this false-positive match, `scripts/test_reference_pdf_coverage.py`
   currently believes `loki` already has adequate source coverage and it is
   NOT in KNOWN_MISSING, so the gap is invisible to CI.

   This is a tooling bug, not a data bug — I did not change loki's own
   family entry, since its notes (LOKI89 by Brown/Pieprzyk/Seberry, AUSCRYPT
   1990, GF(2^8)-based S-boxes, 64-bit block/key, 16 rounds, LOKI91 fixing
   weak keys) match well-established, uncontroversial crypto history and are
   not in question. Two independent things would resolve this fully:
     (a) fetch the actual 1990 LOKI89 paper (or the 1991 LOKI91 revision) and
         add it as references/1990-loki.pdf or similar, or
     (b) at minimum, tighten reference_pdfs.py's fuzzy-match logic (or add an
         explicit exclusion) so "loki" no longer silently matches "loki97"'s
         file, and add `loki` to KNOWN_MISSING in the interim so the gap is
         at least visible and tracked like the other ~79.
   I didn't make this tooling change myself since reference_pdfs.py is used
   by the influence-mining workflow generally, not just this one family, and
   a change there deserves its own focused look rather than a one-off patch
   buried in an unrelated audit pass.

Algebraic/arithmetization-oriented (AO) ciphers: literature review complete,
modeling scoped to 13 core families (2026-07-16)
======================================================================

Per your request to add AO ciphers (block ciphers, hash functions used for
SNARK/STARK/MPC/FHE settings), I did a full citation-crawl literature review
(reading two comprehensive surveys cover to cover: Canteaut et al.'s "Report
on the Security of STARK-Friendly Hash Functions" and Niu et al.'s "SoK:
FHE-Friendly Symmetric Ciphers and Transciphering", CHES 2025 -- both saved
locally) plus several primary papers, and added 13 new families with new
components (power_map_sbox, prime_field_matrix_mul, cauchy_matrix), new
construction taxonomy leaves (algebraic_feistel, alternating_full_partial_
sbox_layer, generalized_triangular_dynamical_system, filter_permutator), new
rounds.yaml entries, and citation-backed influences: mimc, gmimc, hadesmimc,
jarvis, vision, rescue, arion, kreyvium, rasta, flip, masta, hera, poseidon.

I deliberately scoped modeling to this connected, well-documented core rather
than rushing shallow entries for the full ~25-cipher landscape the literature
review actually surfaced. The following are real, citable AO designs I did
NOT add as families -- doing so properly is a similarly-sized follow-up task.
For each I've recorded the exact citation so a future pass doesn't need to
redo the literature search:

1. Rescue-Prime -- Szepieniec, Ashur, Dhooghe, 2020 (not a peer-reviewed
   venue at publication; refined successor to Rescue, already modeled).
2. Poseidon2 -- Grassi, Khovratovich, Schofnegger, AFRICACRYPT 2023,
   eprint 2023/323. Faster successor to Poseidon (already modeled).
3. Starkad -- the GF(2^n) sibling of Poseidon from the same original eprint
   2019/458 design; currently only mentioned in poseidon's/hadesmimc's notes,
   not a standalone family.
4. Anemoi -- Bouvier, Briaud, Chaidos, Perrin, Salen, Velichkov, Willems,
   CRYPTO 2023, eprint 2022/840. Introduces the "Flystel" S-box and "Jive"
   compression mode.
5. Griffin -- Grassi, Hao, Rechberger, Schofnegger, Walch, Wang, CRYPTO 2023,
   "Horst Meets Fluid-SPN", eprint 2022/403.
6. Ciminion -- Dobraunig, Grassi, Guinet, Kuijsters, EUROCRYPT 2021,
   eprint 2021/267 ("Toffoli-gates over large finite fields").
7. Reinforced Concrete -- Grassi, Khovratovich, Luftenegger, Rechberger,
   Schofnegger, Walch, CCS 2022, eprint 2021/1038. First AO hash using
   lookup tables to cut round count.
8. Dasta -- Hebborn, Leander, ToSC 2020(3). Rasta variant using a fixed
   bit-permutation linear layer instead of freshly-random matrices.
9. FiLIP -- Meaux, Carlet, Journault, Standaert, INDOCRYPT 2019. Improved
   Filter Permutator succeeding FLIP (already modeled); Elisabeth/Margrethe
   (Cosseron, Hoffmann, Meaux, Standaert, ASIACRYPT 2022 and successors)
   continue this line with a larger (Z16) plaintext domain.
10. Pasta -- Dobraunig, Grassi, Helminger, Rechberger, Schofnegger, Walch,
    ToSC 2023(3). Successor to Masta (already modeled) with a block-splitting
    strategy; Pasta-v2 further reduces randomness.
11. Rubato -- Ha, Kim, Lee, Lee, Son, EUROCRYPT 2022, eprint 2022/537.
    Fp cipher with Gaussian-noise-based security, related to HERA (already
    modeled).
12. Chaghri -- Ashur, Mahzoun, Toprakhisar, CCS 2022. GF(2^n) block cipher;
    broken by Liu, Anand, Wang, Meier, Isobe's "Coefficient Grouping" attack.
13. Agrasta -- the aggressive round-reduced Rasta parameter set; currently
    mentioned as an instance note under rasta, not benchmarked in its own
    right.
